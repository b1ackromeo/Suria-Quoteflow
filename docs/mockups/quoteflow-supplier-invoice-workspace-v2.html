End-user review of the previous mockup

Too many jobs at once

The old screen mixed invoice queue, file selector, invoice summary, matching, actions, and activity with equal weight. This made the next user action unclear.

Wrong primary controls

Open and Download were not the user task. The user is already previewing, so the viewer should show preview controls and file selection.

Duplicate bundle UI

The old design had document chips and a bundle panel that felt like two places to do the same thing. V2 keeps the actual file work on the left.

Actions appeared too early

Payment action was visible before approval. V2 shows approval/correction actions because that is the current stage.

Better page promise

V2 frames the page as a supplier invoice case: check documents, match invoice, send for approval.

Better document logic

Previewable files get Preview. Non-previewable evidence stays listed but uses Download only where preview is not possible.

Cleaner status logic

The five-step workflow now reflects the real current job: Received, Documents check, Matching, Approval, Payment.

Still to solve

For mobile, this must become tabs: Documents, Preview, Review. The desktop three-column layout should not be squeezed.
